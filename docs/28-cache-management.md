# 数据缓存管理 — 2.0.0

每日实录内容区右上角的「缓存」按钮打开 Basalt 对话框，默认查看当前选中的日期，可切换「所有日期」。按来源显示缓存条数、最近保存时间和单项清除按钮。列表按需读取，打开、切换范围和刷新列表都不查询外部服务。

| 来源 | D1 表 | 日期范围 |
| --- | --- | --- |
| GitHub | `github_day_cache` | 该日期所有账号、时区及 UTC 窗口的完整快照 |
| Gecko / Firefly | `day_source_cache` | 该日期所有时区及 UTC 窗口 |
| 日出日落 / 天气 | `public_context_cache` | 缓存键所指日期的所有位置、时区及 UTC 窗口 |
| 地点名称 | `public_context_cache` | 位置名称跨日期共享，始终展示共享总数，清除影响所有日期 |

条数包括空日快照和已经过期但仍存储的结果；不把尚未完成的 GitHub 查询租约算作缓存。清除仅删除对应来源和范围内已有的结果，其他日期、来源、PAT、设置、导入记录和持久日记均保留。清除不会立即重新查询，也不移除当前已显示的卡片；重新打开当天或刷新页面后按正常策略读取。GitHub 会在手动清除后的下一次读取重新生成完整日快照，此后继续永久复用。

在途查询完成后仍可保存新的结果；管理接口不删除查询租约、公共服务限流行或日记生成租约，不干扰它们的并发协调。

## API

- `GET /api/cache?scope=day&date=YYYY-MM-DD`：查询所选日期及共享地点名称的六类元数据。
- `GET /api/cache?scope=all`：查询所有日期的六类元数据。
- `DELETE /api/cache/{kind}?scope=day&date=YYYY-MM-DD`：清除该类在指定日期的缓存；`place` 是明确标识的跨日期共享例外。
- `DELETE /api/cache/{kind}?scope=all`：清除该类所有日期的缓存。

`kind` 只允许 `github`、`gecko`、`firefly`、`sun`、`weather`、`place`。读取返回 `{ data: { query, entries: [{ kind, count, updatedAt }] } }`，清除返回 `{ data: { cleared, overview } }`，其中 `cleared` 是实际删除条数。时间为 epoch milliseconds；无缓存时为 `null`。响应不包含缓存正文、坐标键、PAT 或密文，并使用 `Cache-Control: no-store`。

日期和范围必填且严格验证；所有日期范围不接受额外日期参数。数据库表名与列名由代码内白名单给定，输入只作为绑定参数。接口经过现有 Access JWT、主机限制和写请求同源校验；机器导入主机无法访问。

不增加迁移，不改变现有缓存过期策略。持久缓存只有在用户明确清除后失效。列表读取复用有界 D1 瞬态恢复。

## 验证

隔离 SQLite 测试验证六种来源、两个日期/时区、多个 GitHub 账号、空日与过期结果、共享地点、重复清除、输入注入拒绝和元数据隐私。清除前后对设置、日记、导入数据和协调行进行逐行比较。

真实 HTTP 检查覆盖 Access、同源和导入主机边界，以及手动清除后 GitHub 恰好重新请求一次并恢复 D1 命中。浏览器覆盖默认日期、所有日期切换、失败重试、清除后卡片保留、无隐式外部查询、键盘焦点恢复、手机布局和可访问性。所有写入验证仅使用隔离测试数据库及合成凭据。

最终检查通过：L1 87 个文件 / 1,561 项测试，四项覆盖率均不低于 96.40%；L2 29 个场景；L3 36 个用例；G1、G2 和生产构建通过。Caddy 的当天/所有日期缓存列表与设置、健康接口均返回 200，未执行真实缓存清除；本地无待执行迁移，原密钥文件内容与 600 权限保持不变。部署证据见 [GitHub 发布记录](27-github.md#验证与发布)。
