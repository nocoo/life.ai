# 分层日记与结构化输出

从 2.0.1 起，日记围绕本人生活组织信息。GPS 与逐笔消费备注是主线，天气和 Apple 健康解释环境与身体活动。Gecko 与 GitHub 的记录数量可能很大，也可能来自机器或 AI 自动执行；它们分别进入独立的开发和 GitHub 卡片。Firefly 的文章即使只有一篇，也必须得到独立分析。

## Gecko 参考

参考相邻 Gecko 项目的 `apps/web-dashboard/src/services/prompt-defaults.ts`、`services/analyze-core.ts` 与 `components/daily/daily-review-client.tsx`：AI 返回固定字段 JSON，服务端解析，页面按字段渲染总结、亮点与时段。Life.ai 沿用这种内容与布局分离的方式，采用生活正文及三张可展开卡片。页面负责标题、Lucide 图标、颜色、段落和列表；模型只负责中文内容。

## 证据优先级

1. GPS 采样与逐笔消费备注先进入 prompt；全部九列账目保留，不能截掉备注尾部或混合不同交易。只有日期的账目不生成交易时刻或先后；预订、代付、退款等按原意解释。
2. 天气、天光、健康维度、跨夜睡眠和其他个人记录提供支持。高频身体采样不写成指标报表；GPS 或睡眠空档不补成确定经历。
3. Firefly 文章先于开发日志进入独立材料区。发表时间只代表公开发表，不能反推写作起点或完成时间。
4. Gecko 的每小时有效活动与 GitHub 项目证据进入各自辅助区，不再重复进入通用事件样本。Gecko 每小时选至多六个应用、每应用两个窗口标题；GitHub 按仓库保留动作数量、首/中/末代表记录和少见 PR 动作，项目详情最多 12,000 字符，超出明确标记覆盖范围。完整事件仍参与日记哈希，原始缓存不变。

正文篇幅按个人线索决定：稀疏日 40–100 字，普通日约 200–450 字，最多约 700 字。只有电脑活动时，正文只用一句、不超过 60 字说明个人活动材料不足，项目细节放在卡片中，不推断通宵、整日工作、持续人工操作或本人监看机器结果。文章可以在正文中自然点到，完整主题留给写作卡片。

## JSON 契约与保存

系统提示词版本：`life-diary-scenes-v8-layered-json`。模型必须只输出 JSON，静默核对语法、转义、字段位置、类型、长度、来源对应关系与信息优先级，不显示自检过程。

```json
{
  "version": 1,
  "narrative": "上午去了菜市场，像是为家里补齐一顿饭的食材。",
  "sections": {
    "development": {
      "summary": "电脑上留下了日记页面的开发线索。",
      "highlights": ["编辑器窗口涉及布局与测试，无法据此前台记录断定持续工时。"]
    },
    "writing": null,
    "github": {
      "summary": "项目的缓存逻辑有了更新。",
      "highlights": ["仓库出现缓存相关提交，可能包含自动化操作。"]
    }
  }
}
```

`src/models/diary.ts` 使用 `JSON.parse` 与 Zod strict objects 校验，拒绝多余或错位字段、缺字段、错误类型、空文本、超长内容及 Markdown 围栏。根字段只能为 `version`、`narrative`、`sections`；版本必须为数字 1。正文最多 2,000 字符；非空卡片的 `summary` 最多 240 字符，`highlights` 必须有 1–5 条非空文字，每条最多 400 字符。

`worker/day-summary.ts` 还校验来源：`development` 对应 Gecko、`writing` 对应 Firefly、`github` 对应 GitHub。有对应记录时卡片必须非空，没有时必须为 `null`；不能凭空创建卡片，也不能漏掉已有的文章记录。任何格式或来源校验失败返回 `502 invalid_diary_format`，释放租约并保留原来整份日记。

新稿 JSON 复用现有 D1 `day_summaries.content` 列保存，无需迁移。API 对新稿返回 `content: narrative` 和 `sections`，界面不显示 JSON 文本；旧的纯文本日记仍按自然段显示。prompt 版本参与原有输入哈希，因此旧稿会提示可重新生成，访问日期不会自动改写。带修改意见时，上份完整文档用于理解修改位置，仍不作为事实证据。

## 展示

生活主文下方依次显示「开发信息」「文章创作」「GitHub 信息」。每张卡片有一句简短概括，默认收起要点，使用 Basalt Collapsible 独立展开；切换日期或生成新稿后重置展开状态。没有对应来源记录时不出现空卡片。图标为 Lucide Monitor、NotebookPen、GitFork；GitHub 沿用现有明暗主题中性色。

当天概况、天气、地图与日记中的说明移到右上角 Lucide Info 控件，天气供应商链接保留在说明内。正文保留测量值、关键日期和可重试的错误。触摸可再次点按关闭，键盘可打开并用 Escape 关闭，面板不会超出视口。

## 验证入口

- L1：结构化文档边界、旧文兼容、格式失败保持 D1 原行、漏写文章拒绝、批量 GitHub 聚合与少见 PR 保留。
- L2：隔离 Worker/SQLite 的真实 HTTP；无效 JSON 和无效字段均返回 502，旧稿不变。
- L3：真实生成/重读、三张卡片独立展开、桌面/手机、键盘/触摸、说明链接、失败后保留以及切日重置。
- 手工模型案例：`scripts/diary-layering-cases.json`，覆盖开发繁忙但生活优先、低频文章与代订反证、纯机器记录的稀疏日。`scripts/eval-diary.ts` 接受分层辅助材料，对新稿校验 JSON，对正文执行原有文风检查；真实付费输出始终保存在仓库外。
