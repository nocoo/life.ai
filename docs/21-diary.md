# 每日日记

本轮把当日 AI 摘要改成有温度、克制的日记。仍由用户手动生成，保存在 D1 `day_summaries`，全来源入账，不受页面筛选影响。

## 证据

生成时收集：

- 天气与日出日落（`worker/public-context.ts`：`getDayWeather` / `getDaySun`，按代表停留点查询）。任一提供者失败只省略该段，其余证据照常写入
- 健康：跨夜睡眠按起床日，保留卧床／实际睡眠／清醒／阶段的区别，并提供今晚入睡。小时步行、爬楼、心率峰值与锻炼起止形成身体活动的时间线；重复锻炼只用 canonical 记录。血氧、呼吸、HRV、静息心率标明是当日观测或样本汇总，不能配上虚构的时刻；心电图、血压保留测量时间与各自单位
- 全部健康 Record 维度另按原类型与单位汇总条数、数值范围和首末观测，避免低频体重、VO₂ max、腕温、噪声提醒等被高频样本挤掉。这些原始范围不能与去重全天总量相加，也不能混合单位；站立小时明确区分达标状态与持续站立时长。复用已经读入的健康事件，不增加 D1 查询
- GPS：最多查询 4 个关键区域的地名（`getPlaceLabel`），按时间给出这些区域的往返记录，不按每个点请求，也不判断家或酒店。最多 24 个定位时段，超出时均匀选取并保留首末；采样空档不代表停留，区间端点不代表实际抵达／离开。只有日期的 GPS 可以作为天气参考位置，但不生成有时刻的停留
- 所有采样时刻按记录精度转换到用户时区：`day` 只有日期，`hour` 只到小时，不用 locale 默认补分钟。全天气温明确最低／最高与资料完整性，不能根据两个极值编造升降温顺序
- 貔貅：紧凑日包 `readPixiuDays` + `pixiuDayEvents`，用 `buildFinanceDay` 按币种独立精确汇总。日常消费仅「日常支出」的流出；支出类流入另列、不可当作退款；转账/还款/余额调整/投资不算消费或收入。日记纳入全部原分类、消费类型和备注，不受界面 6 条备注上限约束，也不截断尾部记录。只有源记账日期，没有交易时刻

旧 `life_events` 里的貔貅在已有紧凑日包时不再重复计入。内容哈希去掉虚拟 `id` / `updatedAt`（Health 与 Pixiu 相同）。

## 输入哈希与公共数据

事件哈希仍是全量记录的 SHA-256。天气、日出日落和地点标签会变，但每次 `GET /api/day-summary` 不得打 Nominatim / Open-Meteo / 太阳 API。

取舍：生成（`POST`）时通过 `getDay*` 拉取并写入 D1 `public_context_cache`；证据收集完成后、调用模型之前折叠缓存指纹并作为保存的 `input_hash`（仅 `SELECT` 已有 JSON，未命中或过期视为 `null`）。模型生成期间缓存变化不算进已保存哈希。查看已保存日记时用同一套 D1 指纹折叠，不调用外部接口。因此：

- 缓存里的天气/太阳/地点变化会让日记变陈旧，提示重新生成
- 尚未写入缓存的外部变化不会出现在 GET 指纹里，避免为了“新鲜”而在阅读路径打上游
- 指纹跟的是缓存内容，不是当次 prompt 里是否成功拼出天气段；生成失败或某段被省略时，仍保留上一则成功日记

## 生成

- `POST /api/day-summary` 可带可选 `revision`（最长 2000 字）
- 再次生成前，界面用 Basalt Dialog 收集修改意见；有意见时服务端带上旧文供理解修改位置，旧文不作为事实来源。未填写意见时直接依据本次原始证据重新写，不继承旧稿中的推断
- 成功覆盖，失败保留上一则；生成租约仍为 90 秒
- 无记录返回 `400 no_records`；他人占用租约 `409 generation_in_progress`

## 文风

从完整材料挑选两到四个生活片段，以第一人称按已知先后叙述，同期的脚步、锻炼与位置放在一起。天气与天光作为背景，消费只按已知用途补充当天的生活，不把每笔金额、定位点数和身体指标逐项复述。正文使用自然中文段落，少量必要数字，不添加因果、出行目的、情绪或空泛收束。仅日期消费不能被配到某次定位或时刻。

查阅旧版 `6cdb344` 及其祖先，没有找到 AI 请求或摘要 prompt；其每日页通过跨来源时间片组织健康、锻炼和 GPS，这一点继续沿用。AI 在 `81dc4c9` 引入，当时要求“客观、精炼、条理清晰的中文日常简报”，按 provider 排列样本。本轮把事件样本改为跨来源时间顺序，并把只有日期的记录独立标注；不继承旧版无睡眠证据时填入起床时间的推断。

2026-09-14 使用 2026-09-13 的生产数据进行真实生成与修改意见重写，核对保存内容、生成时间、输入哈希和再次 GET 的一致性。完整日窗口含 1,597 条虚拟事件；生成失败保留旧文与并发租约由隔离 Worker 测试覆盖。AI 生成是手动操作，浏览日期不会自动生成或覆盖日记。

共享契约仍在 `src/models/ai.ts`。Worker 证据在 `worker/diary-evidence.ts` 与 `worker/day-summary.ts`。
